## Non-negotiable logic lock

The approved presentation changes must not alter:
- grid geometry,
- source partition topology,
- blocked/occupiable semantics,
- clue-dependent furniture/object locations,
- source character placements,
- source clue meaning,
- verified answer identity or coordinate,
- ROOM/ZONE meta-carrier logic.

If any of these changes, the puzzle must be fully revalidated and the visual change cannot be treated as cosmetic.

## Approved small fixes

### 1. Cleaner map field
- Prefer a clean **white paper / white map field** over a gray field that reads dirty in print.
- Pencil marks must remain clearly visible.
- Do not erase or weaken puzzle geometry, furniture, icons or verified scene art while cleaning the paper field.
- Keep grayscale print-safe treatment; no color dependency.

### 2. Larger typography on maps
- ROOM/ZONE names must be **larger and bold**.
- Column letters and row numbers must be **larger and bold**.
- Legend text must be larger.
- Person names/descriptions must be larger.
- A child must never need to infer what a label says.
- Do not solve fit problems by shrinking required text below a comfortable print size.

### 3. Premium Witness Board redesign
The Witness Board currently underuses the full page. Upgrade it from worksheet-like to a premium detective dossier while preserving every fair-play clue.

Required direction:
- stronger case/rank/title hierarchy,
- larger body type,
- bold witness/character names,
- more breathing room,
- evidence-card / witness-statement hierarchy,
- clear mission objective,
- compact Happy Makers banter with distinct voice,
- optional case badge / evidence stamp / mission-status treatment where it improves immersion,
- bottom instruction that solving comes from evidence, not guessing.

The page should feel like a real academy case file, not schoolwork.

### 4. RSE/HMDA witness display-name layer
Public-facing witness/guest names may be changed to a coherent RSE/HMDA naming system.

Rules:
- source/internal person IDs stay unchanged,
- source placement stays unchanged,
- source answer identity stays stored internally and mapped to the public alias,
- clue semantics must remain exactly equivalent after alias substitution,
- solution map, legend, reasoning steps and verdict must use the same public alias consistently,
- within one case, aliases/initials must be visually unambiguous,
- if the map shows initials, no two people in that case may share the same first initial unless the marker system is redesigned and revalidated.

Preferred naming tone: short, memorable, internationally readable, adventurous but not babyish. Candidate pool may draw from:
`Arlo, Bea, Cleo, Dax, Esme, Finn, Gia, Hugo, Ivy, Juno, Kai, Luna, Milo, Nova, Otis, Pippa, Quin, Remy, Suri, Theo, Uma, Vera, Wren, Xavi, Yara, Zuri`.

The goal is a recognizable HMDA universe layer, not random novelty names.
